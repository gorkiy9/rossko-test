# Прототип: выбор курьера при оформлении заказа

Документация интерактивного кликабельного прототипа оформления заказа. Главная фича — блок «Кто привезёт заказ», где пользователь выбирает **умного** или **красивого** курьера (плюс компактная премиум-опция «Красивый и умный»).

## Зачем это

На закрытом тесте клиенты чаще выбирали красивого курьера, а бизнесу выгоднее умный: он допродаёт у двери, снижает возвраты и жалобы. Прототип проверяет гипотезу, что долю умных можно поднять, **показав конкретную пользу умного курьера для товаров в корзине**, не теряя конверсию, честность выбора и WOW-эффект.

Подробно: контекст, допущения, гипотезы и метрики — в [docs/spec.md](docs/spec.md).

## Флоу

```
Корзина → Оформление заказа → Трекинг → Оценка
```

Оформление — одна страница: способ получения и адрес, дата и слот, выбор курьера, получатель, способ оплаты и сводка «Ваш заказ». Состояние заказа (корзина, адрес, слот, курьер, итог) общее для всех экранов.

## Демо-сценарии

Переключаются параметром `?s=A…E` (например, `/#/checkout?s=C`) или панелью «Сценарий» в левом нижнем углу.

| | Сценарий | Что показывает |
| --- | --- | --- |
| A | «Кофемашина» | Умный предвыбран, бейдж с причиной, итог 36 280 ₽ |
| B | «Канцелярия» | Ничего не выбрано, оплата не проходит до выбора курьера |
| C | «Нет красивых сегодня» | Карточка красивого неактивна, кнопка «Выбрать этот слот» |
| D | «Повторный» | Под умным — строка о прошлом опыте |
| E | «Выбран красивый» | Красивый выбран, итог 36 479 ₽, спокойная подсказка |

## Стек и запуск

Vite + React + TypeScript, обычный CSS с CSS-переменными, Tailwind v4 без preflight для компонентов BoardUI. Бэкенда нет, все данные — моки. Деплой не нужен:

```bash
npm install
```

```bash
npm run dev
```

Затем откройте адрес из консоли, например `http://localhost:5173/#/checkout?s=A`.

## Главные ограничения

- Документация описывает прод: изменение интерфейса в `../src` в том же шаге вносится в `docs/spec.md`.
- Не прятать красивого курьера, не усложнять отказ от умного, без подтверждающих модалок и ложного дефицита.
- Сценарии A–E, цены и логику рекомендации не менять без запроса; не придумывать тексты вне spec, бренды и логотипы.

Полный список — в [docs/rules.md](docs/rules.md).
